# Phase 0 — patched build: a linking, runnable nsmonkey

**Date:** 2026-09-21
**Covers:** the final link stage of the MacSurf-patched engine — what the
`07-netsurf-port.md` stack was missing to produce a binary, and the Phase-0
scope decision it forced.
**Status:** **achieved.** `tools/build-patched.sh` builds the full stack
(5 libraries + 6 support libraries + netsurf) and links
`nsmonkey` (13.6 MB, 2026-09-22 11:03 local, 105 patches applied).
Author CSS (inline `<style>` and external `<link>`) now renders — see doc 06 §6.

## 2. Why the link failed, and the decision

After the 104-patch stack applied and every object compiled, the linker
reported **37 undefined symbols**. They split into two families:

1. **~27 `macos9_*` / `macsurf_*` frontend symbols.** The engine calls into
   the Mac OS 9 frontend we deliberately discarded (instrumentation,
   diagnostics, animation, gradients, JS profiling).
2. **7 symbols owned by five core files** MacSurf compiles via its
   CodeWarrior project (`MacSurf.mcp`) but our Makefiles never list:
   `layout_grid.c` (CSS grid), `html_css.c` (external `<link>` CSS),
   `cssh_select.c` (select reset), `html_font.c` (font baseline),
   `macsurf_dom_compat.c` (DOM tag type).

The first instinct was to add those five files to the Makefiles — a quick
win, and each symbol has exactly one owner (no duplicates). Investigation
showed all five are **entangled with the discarded frontends**: atari/amiga
includes, frontend-only symbols, one real indentation bug in `layout_grid.c`,
and `html_font.c`'s libcss enum types coming in through a deleted
`frontends/atari/gemtk/utils.h`. A faithful port is a multi-hour Phase-1
task, each file needing its own review.

**Decision (Phase-0 scope): stub, don't port.** The deliverable is a
*linking, runnable* patched engine proving the whole stack works end to
end; the five capabilities ship in Phase 1 with the Vita frontend.

## 3. The stubs: `compat/macsurf_frontend_stubs.c`

New file, shipped to `content/handlers/html/` by patch 20, listed in the
html Makefile. ~38 symbols:

**Implemented for real (functional, not cosmetic):**

| Symbol | Why real |
|---|---|
| `isDigit`, `isHex`, `charToHex` | libcss's lexer calls these; no-op versions silently break CSS tokenizing |
| `css_error_from_lwc_error`, `css_error_from_parserutils_error` | error-path mapping; cheap to get right (the parserutils one is a 1:1 cast — see doc 06 §1) |
| `lwc_string_caseless_hash_value` | **load-bearing** — per libdom's own comment, CSS selectors never match without it |
| `macsurf__cascade_probe_armed` | plain flag the engine sets around its cascade call |
| `html_css_discover_stylesheets` | **real DOM walk** (2026-09-22) — walks `<style>`/`<link>` and calls the upstream `html_css_update_style` / `html_css_process_link` helpers in `css.c`; author CSS now renders (doc 06 §6) |

**Weak no-ops (the rest):** every `macos9_*`/`macsurf_*` instrumentation,
animation, gradient, memory-diagnostic and JS-profiling symbol. Declared
`__attribute__((weak))` so a future Vita frontend can drop in real
definitions without touching the stubs.

Known functional gaps until Phase 1 (documented, expected, deliberate):
CSS **grid layout** (no-op → block flow), **`<select>` reset**,
**font baseline tuning** (default metrics), **DOM tag-type query** (returns
`UNKNOWN`), **`<input>`/form-control rendering** (L2's `ui` label absent).
Author CSS (inline `<style>` and external `<link>`) is **no longer a gap** —
it was promoted from no-op to real DOM walk on 2026-09-22.

## 4. Durability: what survived re-staging

All fixes live in the patch stack / compat layer, not in the transient
staged tree:

| Fix | Where |
|---|---|
| `git apply`-first application (GNU `patch` mis-handled 1–11 line offsets in git-format diffs) | `tools/apply-patches.sh` |
| pristine-tree staging (`git checkout -- .` before patching; dirty local edits had been corrupting patches) | `tools/build-patched.sh` |
| `pad()` per-element initializer padding + array-branch dedup in the fontstyle-init generator (the `page-info.c` "excess elements" loop) | `tools/gen-fontstyle-init-patch.py`, regenerated `patches/vitabrowser/05-…` |
| verbatim new-file patches with `+` prefixes (the 17/18 corruption) | `tools/gen-handport-patches.py` |
| `ns_errors.h`, `ns_types.h` (MacSurf-new headers the diff generator can't see) | patches 17, 18 |
| `NSUERROR_BAD_INPUT`→`BAD_PARAMETER`, `hlcache_handle` 4th-field init, `MAC_DIR`→`DIR`, missing `<string.h>` | patch 19 |
| frontend/core link stubs + Makefile wiring | patch 20 + `compat/macsurf_frontend_stubs.c` |
| `macsurf_profile_*` no-op stubs | `compat/macsurf_compat.c` / `macsurf_core_decls.h` |
| `-Wno-error=missing-prototypes / implicit-function-declaration / int-conversion` (MacSurf's new files ported from a CodeWarrior baseline) | `tools/build-patched.sh` CFLAGS |

Two subtleties worth keeping:

- **Patch 19's llcache section is only the `macsurf_debug_log_writef`
  extern.** The `BAD_INPUT`→`BAD_PARAMETER` renames and the removal of
  MacSurf's local `nsu_base64_*` bodies (which duplicate
  `libnsutils/base64.c` and fail the link with multiple definitions) are
  *already carried by the generated MacSurf-vs-upstream stack* — re-adding
  them to patch 19 makes its hunks redundant on the clean path and the
  `--forward` fallback marks the patch failed while applying nothing.
- **`struct box;` / `struct content;` forward declarations** sit at the top
  of the stubs: the parameters are pointer-only, and pulling in
  `layout.h`/`content.h` drags frontend-entangled includes into a file that
  exists specifically to avoid them.

## 5. What this does *not* prove

- Rendering parity. Measured 2026-09-22 (doc 06): L1 byte-identical to the
  pristine golden; L2/L3/L4 differ where the stack adds behavior (value
  functions, grid/flex reflow) plus the `<input>` gap.
- The four remaining stubbed capabilities (grid, select reset, font
  baseline, tag type) work — they don't; that is the Phase-1 work list.
  (Author CSS, formerly fifth on this list, now works.)
- Vita. The build is the Linux monkey frontend; `TARGET=macos9` is gone and
  the Vita frontend is not started.

The claim this doc makes is narrow and true: **the patched engine compiles,
links, and produces a runnable nsmonkey from a clean upstream checkout,
fully from the documented patch stack.** Everything above it is Phase 1.
