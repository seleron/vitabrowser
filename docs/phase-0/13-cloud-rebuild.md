# 13 — Rebuilding from the repo alone (cloud session, 2026-09-27)

The build loop paused on 2026-09-27 ~12:57 with Patch 131 (B1 streaming)
mid-flight: its C/JS edits existed only in the desktop's applied tree
(`<WORK>/vitabrowser-work/applytest/upstream/netsurf`), which is uncommitted by
design. The desktop was offline, so this session rebuilt everything from
the repository and GitHub, then re-did Patch 131 from scratch. This
document records what that took, because a from-scratch rebuild had never
been done before and it found three problems.

## 1. Reproducing the work tree: `tools/bootstrap-work.sh`

The original trees came from `git://git.netsurf-browser.org` and their
revisions were never recorded (docs 01, 02). The cloud runner cannot reach
netsurf-browser.org, savannah.gnu.org, curl.se or web.archive.org
(egress policy), so the script uses GitHub only:

| Input | Source | Pin |
|---|---|---|
| libwapcaplet, libparserutils, libhubbub, libcss, libdom, netsurf, libnsutils, libnsgif, libnsbmp, libnspsl, libsvgtiny, nsgenbind, buildsystem | `github.com/netsurf-browser/*` mirrors | commits in the script; all predate 2026-09-20 |
| libutf8proc | **not mirrored**: `JuliaStrings/utf8proc` v2.9.0 behind a `GNUmakefile` shim | same API for the four calls `utils/idna.c` makes |
| MacSurf `browser/` | `mplsllc/macsurf` | `55e64fa` (unchanged) |

With these pins the committed stack applies **215/215** and
`nsvita-sim` builds.

### Finding 1: the MacSurf patches assume BUILT upstream trees

On freshly cloned trees `libcss/08-parse-properties.patch` and
`libhubbub/04-treebuilder.patch` fail with "can't find file to patch".
They patch files the build generates (libcss's `autogenerated_*.c` from
`properties.gen`, libhubbub's `autogenerated-element-type.c` via gperf).
Those files are gitignored, so the desktop's "pristine" trees (built in
place during Phase 0) passed `build-patched.sh`'s `git status` check while
still carrying them, and `split-patches.py` diffed against them.

Fix: `bootstrap-work.sh` builds the five core libraries in place once
(needs `gperf`), which recreates the files; the trees stay git-clean.

### Finding 2: patch 46 was corrupt, masked by the in-place workflow

`a45dc70` (Patch 130) hand-edited `46-netsurf-vita-quickjs-bridge.patch`
to add the "re-read `vita_window_current()` after `vita_schedule_run()`"
fix. It added 6 lines but changed the hunk header from `+834,10` to
`+834,12` (should have been `+834,16`), so `git apply` reported "corrupt
patch at line 334" and GNU `patch` rejected it. The desktop never noticed
because its applied tree is edited in place and not re-applied from the
repo. The broken patch also cascaded: 47, 48, 49, 50 and 54 failed after it.

The fix also belonged to Patch 130, not 46: `vita_window_current()` only
exists after the popup patches (126/127). So patch 46 is restored to its
pre-`a45dc70` text, and the fix moves to the end of patch 130. It now
re-reads `bw` as well as `gw`, since a closed popup frees its
browser_window too and `bw` was derived from the freed `gw`.

**Lesson (hard rule proposal):** never hand-edit an old patch file. Put
late fixes in the newest patch, and after any patch commit run
`tools/apply-patches.sh` on a fresh stage (`tools/build-patched.sh` does
this).

### Finding 3: `nsmonkey` no longer links

`build-patched.sh`'s final `nsmonkey` link fails on symbols only the Vita
frontend provides (`js_fire_window_load`, `js_link_frame_heaps`,
`svgtiny_*`). The simulator (`run-vita-sim.sh`) doesn't need the monkey
binary (it needs the prefix and the patched tree), so this is cosmetic. It
does mean the golden-plotstream checks (doc 03) have not run since the
QuickJS bridge landed.

### Script changes for sandboxed machines

- `build-patched.sh`: `SKIP_REGEN=1` builds the committed stack as-is
  instead of regenerating the MacSurf patches first.
- `build-host-freetype.sh`: falls back to SourceForge for the same
  tarball (the SHA256 pin is the check).
- `fetch-certs.sh`: `CA_BUNDLE_LOCAL=<file>` stands in for the pinned
  Mozilla bundle, with a loud warning. Simulator only: never package a VPK
  built this way.

Full recipe on a new machine:

    apt-get install gperf flex bison      # plus the usual build tools
    tools/bootstrap-work.sh
    SKIP_REGEN=1 tools/build-patched.sh   # nsmonkey link failure is expected
    CA_BUNDLE_LOCAL=/etc/ssl/certs/ca-certificates.crt tools/run-vita-sim.sh
